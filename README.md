# feed-preview

Минималистичный сервис для публикации и демонстрации постов и историй Instagram. У каждого проекта своя ссылка, которую можно отправить клиенту.

- **Посты** — фото 4:5 и видео MP4, WebM или MOV; до 10 медиафайлов в карусели. Поддерживаются тема, дата публикации и подпись.
- **Истории** — формат 9:16, фото и видео до 10 медиафайлов с переключением стрелками, тема, дата и черновой текст рядом с медиафайлом. При добавлении не нужно выбирать кружок; текст будет добавлен к истории при публикации.
- **Представления** — лента с вкладками «Посты» и «Сторис» открывается по умолчанию. Календарь показывает темы в ячейках дат и открывает список публикаций по нажатию. Сетка временно скрыта.
- **Проекты** — главная страница со списком, у каждого проекта ссылка вида `/p/kofeynya-utro-5c26`.

## Запуск

Нужен Node.js 18+.

```bash
npm install
npm start
```

Откройте http://localhost:3000.

## Настройки (переменные окружения)

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `PORT` | `3000` | порт сервера |
| `ADMIN_PASSWORD` | не задан | пароль редактора; локально задаётся в игнорируемом `.env`, в Cloudflare — через secret |
| `DATA_DIR` | `./data` | где хранятся база (`db.json`) и загруженные фото |
| `TRUST_PROXY` | не задан | поставьте `1`, если сервис стоит за nginx/Cloudflare и т. п. |
| `SESSION_SECRET` | из пароля локально | секрет подписи входа; в Cloudflare обязателен отдельный secret |

Для локального запуска укажите `ADMIN_PASSWORD=ваш-пароль` в файле `.env` рядом с `server.js`. Этот файл исключён из Git. Можно также задать `ADMIN_PASSWORD` в окружении перед `npm start`.

## Доступ и безопасность

- Если локальный `ADMIN_PASSWORD` не задан, редактирование заблокировано.
- В Cloudflare Worker запуск блокируется, пока не заданы secrets `ADMIN_PASSWORD` и `SESSION_SECRET`.
- Ссылка проекта `/p/...` всегда открывает клиентский режим просмотра. Ссылка `/p/.../admin` открывает вход для редактирования:
  - страницы проектов (`/p/...`) открываются по ссылке в режиме просмотра, без кнопок редактирования;
  - список всех проектов доступен после входа администратора;
  - API проверяет доступ к изменениям отдельно от скрытия кнопок в интерфейсе.
- Ссылки на проекты содержат случайный хвост, но это не защита: у кого есть ссылка, тот видит проект. Сайт закрыт от индексации (`noindex`, `robots.txt`).

## Как пользоваться

1. На главной нажмите **«Новый проект»**, введите название.
2. **Пост:** нажмите «Новый пост» в ленте или плитку **+** в сетке → выберите до 10 фото и видео → настройте кадрирование фото (4:5); видео добавляются без кадрирования → задайте тему, дату и подпись → «Опубликовать».
3. **История:** нажмите «Новая история» → выберите до 10 фото и видео, настройте кадрирование фото (9:16) → рядом с медиафайлами укажите черновой текст, тему и дату.
4. В меню проекта доступны отдельные команды копирования клиентской и админской ссылок.
5. В подробном просмотре поста и истории (для редактора) доступны редактирование текста и удаление. Для существующих кружков также доступны переименование и удаление.

В просмотре историй: клик по левому краю — назад, по правому — вперёд, удержание — пауза, стрелки на клавиатуре, `Esc` — закрыть.

## Как устроено

```
server.js        Express-сервер: API, раздача страниц, загрузка фото
worker.mjs      Cloudflare Worker entry point
wrangler.jsonc   Cloudflare D1/R2/assets bindings
migrations/      схема D1
public/
  index.html     единственная HTML-страница
  style.css      оформление (светлая и тёмная тема по настройкам системы)
  app.js         весь интерфейс на чистом JS, без сборки
data/            создаётся при запуске: db.json + uploads/
```

- Фото обрезаются в браузере и уходят на сервер уже готовыми JPEG: **1080×1350** для постов и **1080×1920** для историй.
- Локальный запуск хранит проекты в `data/db.json`, медиа — в `data/uploads/`; папки `data/` достаточно для локальной резервной копии.
- В Cloudflare проекты, посты и сторис хранятся отдельными строками в D1, медиафайлы — в R2. Кнопки экспорта/импорта сохраняют и восстанавливают базу вместе с медиа.
- Если `db.json` повредится, сервер не запустится и не затрёт файл молча.

## Размещение на хостинге

Для публикации подготовлена схема Cloudflare Workers + D1 + R2. Она оставляет API и сайт на одном домене, а проекты сохраняет в D1, медиа — в R2. GitHub хранит исходный код и запускает автоматическую публикацию через Actions. GitHub Pages сам по себе не запускает Express API и не подходит для текущей загрузки фото и видео.

### Первый запуск Cloudflare

Нужны бесплатный аккаунт Cloudflare и Wrangler (`npx` установит CLI при первом запуске). D1 уже привязана в `wrangler.jsonc`; имя базы должно быть `feed-preview-db`.

1. Войдите в Cloudflare командой `npx --yes wrangler@4 login`.
2. Создайте хранилище медиа: `npx --yes wrangler@4 r2 bucket create feed-preview-media`.
3. Задайте пароль администратора: `npx --yes wrangler@4 secret put ADMIN_PASSWORD` и введите свой пароль в приглашении CLI.
4. Задайте секрет сессии: `npx --yes wrangler@4 secret put SESSION_SECRET` и введите случайную строку длиной не менее 32 символов. Не публикуйте эти значения и не добавляйте их в GitHub.
5. Примените схему и опубликуйте приложение: `npx --yes wrangler@4 d1 migrations apply feed-preview-db --remote`, затем `npx --yes wrangler@4 deploy`.

Для автоматических публикаций откройте GitHub → `mariiasmm/mariiasmm` → **Settings → Secrets and variables → Actions → New repository secret**. Добавьте `CLOUDFLARE_API_TOKEN` и `CLOUDFLARE_ACCOUNT_ID`. Для токена используйте права **Workers Editor** и **D1 Editor** на нужном аккаунте. До добавления обоих секретов workflow пропускает deploy; после добавления запустите его один раз в **Actions → Deploy to Cloudflare Workers → Run workflow**, а следующие изменения в `main` будут публиковаться автоматически.

Перед первым переносом откройте локальный сайт, войдите на главной странице и выберите **Экспорт базы данных** в меню. На опубликованном сайте откройте главную страницу, войдите тем же паролем и выберите **Импорт базы данных**. Импорт восстановит проекты, посты, сторис и медиа в Cloudflare; исходная локальная папка `data/` останется на компьютере. Резервная копия и медиа намеренно не хранятся в GitHub.

Бесплатный тариф ограничен квотами Cloudflare. В частности, D1 ограничен 500 МБ на базу, R2 включает 10 ГБ хранения, а Workers Free — 100 000 запросов в день. Если проект вырастет сверх квот, Cloudflare остановит операции, требующие превышенного лимита, либо предложит перейти на платный тариф.

## Ограничения

- В одном посте или сторис может быть до 10 медиафайлов.
- Видео принимаются в форматах MP4, WebM и MOV, размер одного файла — до 100 МБ.
- Форматы фото: JPG, PNG, WebP; HEIC браузеры обычно не открывают, сначала конвертируйте.
- Один общий пароль на всех редакторов, без отдельных аккаунтов.
